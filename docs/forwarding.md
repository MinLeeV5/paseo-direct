# 经 VPN 电脑中继访问目标主机

Paseo Direct 1.1.0 起提供主机转发，1.2.0 起提供自动优先与回退。中继复用 Paseo 的主机转发（`routed`）能力，B 和手机 App 都需支持该能力。插件运行时会检查接口；不支持时停止操作并提示。

## 三台设备的连接关系

| 设备 | 地址 | 作用 |
| --- | --- | --- |
| A：目标电脑 | `172.20.98.10:6767` | 运行目标 Paseo daemon，通过 frpc 映射到 `10.23.11.104:16767` |
| B：中继电脑 | `192.168.1.64` | 运行 Paseo，登录 VPN，能访问 `10.23.11.104:16767` |
| C：手机 | `192.168.1.65` | 先通过局域网直连 B，再经 B 访问 A |

实际请求路径为：

```text
C → B 的 Paseo 局域网监听端口 → B 的 VPN → 10.23.11.104:16767 → frp → A:6767
```

C 不需要登录 VPN，也不需要拥有到 `10.23.11.104` 的 IP 路由。手机保存的是到 B 的连接和“经 B 到 A”的主机转发连接。B 无需额外开放一个原始 TCP 代理端口。

## 配置步骤

1. 在 B 上完成 VPN 登录，确认 **B 的 Paseo daemon 所在进程**能访问 `10.23.11.104:16767`。仅浏览器或桌面客户端可用的应用代理不一定能被 daemon 使用；VPN 必须给该进程提供目标路由。
2. 在 B 安装 Paseo Direct 1.2.0：`paseo plugin add git:MinLeeV5/paseo-direct --ref v1.2.0`。已通过 Git 安装的 B 使用 `paseo plugin update paseo-direct --ref v1.2.0` 升级。A 无需为主机转发安装此插件；A 若也安装插件，建议一起升级，以协调直连与中继偏好。
3. 手机 C 与 B 完成 Paseo 配对。在 **B 的 Paseo Direct** 页面，使用自动探测或地址的“连接”按钮，让当前连接变为 B 的局域网直连。假设 B 的实际监听端口为 `6767`，地址应是 `192.168.1.64:6767`；以 B 的实际监听配置为准。
4. 仍在 B 的插件页面，展开 **通过此 PC 中继**。目标地址填 `10.23.11.104:16767`，名称可填 `电脑 A`。若 A 需要认证，单独填写 **A 的 Paseo 密码**，然后保存。此处不填写 VPN 账号密码。
5. 等待状态变为 **此 PC 已连接到目标**。手机 App 会从 B 的主机目录发现 A。先确认手机已通过 A 原有的 Relay 或直连方式配对，能在 B 不可用时独立连接 A。仅有经 B 的路由无法提供独立回退，插件会要求补充原有配对。
6. 在 B 目标列表开启 **自动优先此中继**，再在侧边栏选择 A。若 A 也安装了插件，可在 A 的页面选择 **优先使用的中继电脑 → B**，效果相同。若刚连接成功而 App 尚未发现路由，稍候重试。“使用此中继”仍可用于单次手动切换。

由 B 添加目标是 PC 共享配置；自动优先来源仅按 **当前手机 × 目标 A** 保存，一个目标只能选一个来源。A 在手机上已有 Relay 配对时，会按同一个 `serverId` 合并转发连接，已有连接继续保留。关闭插件页面后策略仍在 App 前台运行，不需要一直停留在 B 页面。

## 自动优先、回退与恢复

- 手机到 B 必须实际使用在线直连。B 经公网 Relay 在线时，插件使用 A 的原有连接；不会把 B 的在线状态当成局域网可达。
- 切换前验证经 B 到 A 的通道、目标身份与往返响应，再将已验证的连接交给 Paseo。B 的 VPN 断开、目标通道失效或手机到 B 的直连断开时，插件验证并激活 A 已保存的非转发路径，复用 Paseo 的认证信息。
- A 的原有路径也不可达时显示“原有连接也暂时不可达”，保留所有连接并继续重试。没有可用网络时无法保证连接成功。
- 正常时按目标设备设置的探测间隔检查通道，连接状态变化会触发提前检查。失效后至少等待 30 秒再尝试优先中继；连续失败最长退避 300 秒。B 恢复后会在后续检查与退避结束时自动恢复中继，优先策略不承诺无中断切换。
- “自动寻找直连”与自动中继是独立开关。为 A 设置中继偏好后，A 的直连探测只保存新地址，避免覆盖中继优先级。手动选择 Relay 或指定直连会暂停自动中继 60 秒。
- 取消中继偏好或停用插件会停止优先策略，已经保存的路径继续由 Paseo 自身管理；不会删除路由条目或目标配对。后台停止插件主动探测，回到前台重新检查。

如果只想立即使用 Paseo 已有能力，也可在 B 上执行以下命令（适用于 A 无需 Paseo 密码的场景）：

```sh
paseo host add tcp://10.23.11.104:16767 --label "电脑 A"
paseo host ls
```

这是 B 的原生主机配置，手机连接 B 后由 Paseo 自动发现。CLI 添加的目标由 Paseo 自身管理，不在插件的目标列表中；插件只管理自己添加的记录。需要密码时优先使用插件的独立密码输入框。

## 保存、移除与连接边界

- 目标连接及必要的 Paseo 密码由 B 的原生主机注册表保存，插件重载后继续生效；插件停用或卸载也不会自动删除原生目标。输入框提交后清空密码，目标状态和插件诊断不返回密码、连接 URI 或底层错误内容。
- B 是受信任的中继：获准使用 B 的客户端可经 B 访问其共享目标。VPN 仍由 B 负责登录和续期；退出 VPN、B 关机或休眠都会使此路径不可用。路径是否更快取决于实际网络延迟。
- 为保持局域网路径，C 到 B 应使用直连。如果 C 到 B 使用公网 Relay，手动中继也可工作，但仍包含该 Relay 路径，不符合自动优先的条件。仅属于相同网段不能证明可达，还需允许局域网访问并开放 B 的实际 Paseo 端口。
- 本入口按一层主机转发设计。Paseo App 不会从已配置为转发目标的主机继续递归发现其他目标；请将 B 直接配对到手机，避免组成多层路由链或循环。
- 最多通过插件添加 16 个目标。重复保存同一个地址及 TLS 设置时保留原连接与密码；修改地址或密码需移除旧目标后重新添加。需要 TLS 时填写匹配证书的 `wss://域名:端口`。
- 移除目标会断开所有客户端经 B 到该目标的路由，但不删除 A 上的会话。App 可能保留已发现的路由条目，可在 Paseo 的主机连接设置中清理；不用此来源时也应关闭自动优先。启用策略时插件会恢复已保存且验证可用的原有路径，Paseo 也会继续探测其连接。

## 常见状态

| 状态 | 检查方向 |
| --- | --- |
| 无法读取中继目标 | B 与 App 版本是否支持主机转发、手机是否在线连接 B、插件是否已更新 |
| B 无法连接目标 | B 的 VPN 是否已登录、daemon 是否能使用该 VPN、frpc 映射是否正常、A 的 Paseo 密码是否正确 |
| B 在线但手机尚未发现目标路由 | 稍候重试，确认手机直接配对 B，且 B 未被配置为其他主机的转发目标 |
| 手机仍通过 A 的原有 Relay 连接 | 开启“自动优先此中继”，确认手机实际直连 B、目标在线、未处于手动暂停或故障退避；也可点击“使用此中继”手动验证 |
| 要求保留原有配对 | 手机当前只有经 B 的路由，请先配对 A 的 Relay 或手机可直接访问的地址 |

自动化覆盖目标去重、凭据隔离、原有记录保护、两段失效、回退、恢复、前后台与重载退避；独立 daemon 验证覆盖真实密码认证与路由请求。用户这组 VPN / frp 链路和手机真机仍需在各自设备上验收。
